### 桁・数字の入れ替えを疑う

- **差額が9の倍数**
  - 例：現金とレシートの差が **90円、180円、450円**
  - `54 → 45`、`120 → 210` のような**数字の転置**では、差が必ず9の倍数になる。
  - 例：`54 - 45 = 9`
  - 例：`721 - 271 = 450`

- **差額が99の倍数**
  - 百の位と一の位など、離れた桁の取り違えを疑える。
  - 例：`123 → 321`
  - 差は `198 = 99 × 2`

- **差額が10倍・100倍付近**
  - 小数点、単位、桁位置の間違いを疑う。
  - 例：`1,250円 → 12,500円`
  - 例：`2.5kg → 250g` の変換ミス。

- **0が1個多い／少ない**
  - 入力ミスとして非常に多い。
  - `5000 → 50000`
  - 金額、数量、単価ではまず確認する。

---

### 9を使って検算する

- **各桁を足して9で割った余りを比較する**
  - いわゆる「九去法」。
  - 足し算・引き算・掛け算の簡易チェックに使える。
  - 例：
    - `123 × 45 = 5535`
    - 123 → `1+2+3=6`
    - 45 → `4+5=9 → 0`
    - `6×0 → 0 mod 9`
    - 5535 → `5+5+3+5=18 → 0`
  - 一致しているので少なくともこの検査には通る。
  - ただし、**一致しても正解とは限らない**。

- **3でも同じ検査ができる**
  - 9より検出力は弱いが暗算しやすい。
  - 「3の倍数になるはずなのになっていない」だけでも誤りを発見できる。

---

### 偶奇だけを見る

- **偶数＋偶数＝偶数**
- **奇数＋奇数＝偶数**
- **偶数＋奇数＝奇数**
- **偶数×何か＝偶数**
- **奇数×奇数＝奇数**

結果の偶数・奇数がおかしければ、その時点で計算ミス。

例：

`37 × 51`

は奇数×奇数なので、答えは必ず奇数。

`1886` と出たら、詳しく検算するまでもなく間違い。

### 末尾の数字だけを見る

- **掛け算は1の位だけ再計算する**
  - `37 × 24`
  - 末尾は `7×4=28` なので答えの1の位は必ず **8**。
  - `884` と出ていたら即アウト。

- **5を掛けた数**
  - 必ず下一桁が0か5。

- **10を掛けた数**
  - 必ず0で終わる。

- **25を掛けた整数**
  - 下2桁は `00 / 25 / 50 / 75` のどれか。

---

### 割り切れるはずかを見る

- **2の倍数** → 下一桁が偶数
- **3の倍数** → 各桁の和が3の倍数
- **4の倍数** → 下2桁が4の倍数
- **5の倍数** → 下一桁が0か5
- **8の倍数** → 下3桁が8の倍数
- **9の倍数** → 各桁の和が9の倍数
- **10の倍数** → 下一桁が0
- **11の倍数** → 奇数桁と偶数桁の和の差が11の倍数

「本来○○の倍数になる計算」なら非常に強力。

### オーダーを見る

- **概算して桁数を見る**
  - `498 × 203`
  - 約 `500 × 200 = 100,000`
  - 答えが `10,094` や `1,009,400` なら、細かく検算する以前に怪しい。

- **最大値・最小値から外れていないか**
  - 80～100円の商品を10個買ったなら、
    - 最低800円
    - 最大1000円
  - 合計が1200円なら明らかにおかしい。

- **平均値は最小値と最大値の間にある**
  - 10、20、30の平均が40になることはない。

- **割合は母数を超えない**
  - 通常の「構成比」なら合計100%。
  - 120人中80人なら約67%であり、167%にはならない。

### 逆算する

- **足し算は引き算で確認**
  - `A+B=C`
  - `C-B=A` を見る。

- **掛け算は割り算で確認**
  - `A×B=C`
  - `C÷B=A`

- **値引き計算を元に戻す**
  - 20%引き後が8000円なら、
  - `8000 ÷ 0.8 = 10000円`

同じ計算をもう一度やるより、**逆演算した方が同じミスを繰り返しにくい**。

---

### 順序を変えて計算する

- **足し算の順番を変える**
  - `123+456+789`
  - もう一度同じ順番で計算せず、
  - `789+123+456`
  - とする。

- **まとめ方を変える**
  - `48+52+97+103`
  - `(48+52)+(97+103)`
  - `=100+200=300`

同じアルゴリズムを繰り返すと、同じミスを再現しやすい。

---

### 単位を見る

- **円＋個は足せない**
- **km ÷ h は km/h**
- **単価×数量＝金額**
- **面積なら単位は二乗**
  - `m × m = m²`
- **体積なら三乗**
  - `m × m × m = m³`

計算結果の単位がおかしければ、式そのものがおかしい可能性が高い。

---

### 比率を見る

- **10%なら元の値の約1/10**
  - 8,000円の10%が8,000円になることはない。

- **1%なら1/100**
  - 300万円の1% ≒ 3万円。

- **倍になれば、おおむね結果も倍になるか**
  - 線形な計算なら非常に有効。

入力を2倍にしたのに結果が10倍になっていたら、式や参照セルを疑う。

---

### 合計値の性質を見る

- **小計の合計＝総計**
- **内訳の構成比合計＝100%**
- **入金－出金＝残高増減**
- **期首残高＋増加－減少＝期末残高**

会計や在庫では、別ルートで同じ値になる「突合ポイント」を作る。

---

### 件数を見る

例えば、

`単価 × 数量 = 売上`

なら、

`売上 ÷ 単価 ≒ 数量`

として、数量が整数になるはずなのに

`37.428571個`

などになった場合、どこかがおかしい可能性が高い。

---

### 符号を見る

- 利益なのにマイナス
- 値引きしたのに価格が増える
- 人数がマイナス
- 在庫があり得ないほど負になる
- 距離や時間が負になる

数学的には成立しても、**現実世界の制約に反していないか**を見る。

### 前回値・過去値と比較する

- 前月100万円 → 今月1億円
- 昨日100件 → 今日10,000件
- 平均70kg → 今回700kg

「前年差」「前月比」「前回比」を表示するだけで桁ミスをかなり発見できる。

特に、

**約10倍、約100倍、約1/10、約1/100**

は単位・小数点・桁入力ミスを強く疑う。

---

### 人間向けには「きれいすぎる数字」も疑う

実測値や大量データなのに、

- すべて下一桁が0
- 平均がちょうど100.000
- 100件の合計がちょうど1,000,000
- パーセンテージが全部整数

などの場合は、

**丸め処理・切り捨て・コピー・固定値入力**

を疑う価値がある。

---

### 表計算では「縦横の総計」を作る

例えば売上表なら、

| | A店 | B店 | C店 | 合計 |
|---|---:|---:|---:|---:|
| 商品1 | | | | |
| 商品2 | | | | |
| 商品3 | | | | |
| 合計 | | | | 総計 |

縦方向から求めた総計と、横方向から求めた総計が一致することを確認する。

これは古典的だが非常に強い。

---

### 最後に最も強力な原則

**「同じ計算をもう一度やる」のは、意外と弱い検算方法。**

人間は同じ思考手順だと同じ間違いを再現するため、

- 逆算する
- 概算する
- 末尾だけ確認する

- 単位を見る
- 別集計と突合する
- 上限・下限を見る

というように、**別の性質から答えを攻撃する方が計算ミスを発見しやすい**。
